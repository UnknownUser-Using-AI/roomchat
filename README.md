# roomchat

실시간 공개 채팅방입니다. 지정된 **「슬랩배틀 라이벌 입양 피기」** 방을 맨 위에 고정하고, 누구나 게스트 또는 닉네임·비밀번호 계정으로 참여할 수 있습니다. 정적 웹 파일은 GitHub Pages에, 방·메시지·계정 프로필은 Supabase에 저장됩니다.

## 기능

- **게스트**: 닉네임을 바꾸고 방을 만들 수 있습니다. 같은 탭에서 새로고침해도 닉네임을 복구하지만 계정 프로필로 저장하지는 않습니다. 12시간 이상 활동이 없거나 탭을 닫으면 다시 입력해야 합니다.
- **계정**: 이메일 입력 없이 닉네임과 비밀번호로 가입·로그인합니다. 비밀번호는 Supabase Auth가 해시하여 보관하고, 사이트는 실제 이메일 주소를 요청하거나 저장하지 않습니다. 계정 닉네임은 보존되고 변경할 수 있습니다.
- **닉네임 보호**: 중복되거나 제어문자·링크·부적절한 표현 등 사용이 제한된 이름은 원래 이름 뒤에 숫자를 붙이지 않고 `크리스탈 시청자`로 자동 변경합니다. 해당 이름도 사용 중이면 `크리스탈 시청자 2`처럼 빈 이름을 선택합니다.
- **인증 관리자**: 관리자 계정은 각각 `천사` 또는 `크리스탈`로 최초 가입하고 일회용 초대코드를 사용합니다. 화면에서는 닉네임과 분리된 `[인증됨]` 배지가 표시되며, 두 관리자만 굵은 무지갯빛 닉네임·관리자 권한을 받습니다. 두 관리자는 닉네임을 언제든 바꿀 수 있고 인증 배지는 유지됩니다. 다른 계정은 `인증됨` 문구를 닉네임에 사용할 수 없습니다.
- **방 운영**: 게스트와 계정 모두 공개 방을 만들 수 있습니다. 방을 만든 사람은 그 방의 운영자로서 참가자를 내보낼 수 있고, 관리자는 어느 방에서나 이를 수행할 수 있습니다.
- **관리자 도구**: 관리자는 활동 중인 이상한 닉네임을 `크리스탈 시청자`로 정리하고, 메시지 및 고정 기본방을 제외한 방과 그 대화·첨부 이미지를 삭제할 수 있습니다.
- **실시간 채팅**: Supabase Realtime으로 메시지와 참여자 수를 갱신하고, 최근 100개 메시지를 불러옵니다. 이미지 붙여넣기·파일 첨부는 JPEG/PNG/WebP/GIF/AVIF, 최대 8MB를 지원합니다.

## 보안 및 공개 범위

모든 방, 메시지, 프로필 닉네임 및 공유 이미지는 공개 채팅용 데이터입니다. 비밀번호는 메시지 테이블에 저장하지 않으며, 인증된 역할·닉네임·방장 토큰·게스트 세션 토큰은 브라우저에서 임의로 부여할 수 없습니다. 참가자 명단과 인증 표시는 Realtime이 보낸 임의 필드가 아니라 서버가 확인한 프로필·세션으로 만듭니다. DB 쓰기는 권한을 검사하는 RPC를 거치며 일반 브라우저 클라이언트에는 Supabase `service_role` 키가 들어 있지 않습니다.

닉네임 제한은 제어문자, URL 형식, 과도한 기호 및 기본 부적절 단어 목록을 이용한 자동 필터입니다. 채팅 이미지 업로드는 기존 방의 UUID 경로와 허용된 이미지 확장자로 제한합니다. 자동 판정이 놓친 방·닉네임·대화는 관리자가 직접 정리할 수 있습니다. 고정 기본방은 일반 운영 중 실수로 사라지지 않도록 관리자 삭제 대상에서 제외했습니다.

## Supabase 배포 순서

SQL 변경은 기존 사이트와 이용 기록을 보존하며 기능을 단계적으로 추가합니다. 기능 마이그레이션 뒤 관리자 배지와 이름 변경을 분리하는 보정 마이그레이션을 적용하고, 새 사이트가 연결된 뒤 기존의 익명 직접 쓰기 권한을 제거합니다.

1. `feature_migration.sql`을 Supabase 프로젝트 `losuyalyjcurntylbwgy`에 적용합니다. 기존 방과 메시지는 삭제·변경하지 않고, 지정 고정방 및 프로필·권한·세션 함수만 추가합니다.
2. `admin_name_badge_migration.sql`을 적용합니다. 관리자 최초 이름을 `천사`/`크리스탈`로 저장하고 `[인증됨]`을 분리된 배지로 표시하며, 이름 변경 후에도 관리자 인증을 유지합니다.
3. `supabase/functions/roomchat-auth/index.ts`의 `roomchat-auth` Edge Function을 `verify_jwt=false`로 배포합니다. 이 함수는 누구나 호출할 수 있는 가입·로그인 창구지만, 비밀번호 인증과 일회용 관리자 코드를 서버에서 검증합니다. `service_role` 키는 Edge Function에서만 사용해야 합니다.
4. 저장소 루트의 `index.html`, `app.js`, `styles.css`를 GitHub Pages에 배포합니다.
5. 새 앱이 작동하는 것을 확인한 다음 `security_migration.sql`을 적용합니다. 방·메시지 테이블과 메시지 ID 시퀀스의 직접 쓰기·TRUNCATE·트리거·참조 권한을 `PUBLIC`, `anon`, `authenticated`에서 회수하고, 방·메시지는 읽기 전용으로 둡니다. 쓰기는 권한을 검사하는 서버 RPC만 사용합니다.

`migration.sql`은 기존 기본 스키마입니다. 이미 적용된 운영 프로젝트에서 다시 실행할 필요는 없습니다. 웹의 공개 publishable key는 `config.js`에 두어도 되지만 `service_role` 키·비밀번호·일회용 관리자 초대코드는 공개 저장소에 올리지 마세요.

## GitHub Pages

현재 고정 주소는 <https://unknownuser-using-ai.github.io/roomchat/> 입니다. 모든 웹 파일은 저장소 루트에 있고, GitHub **Settings → Pages → Deploy from a branch → `main` → `/(root)`**로 배포합니다. 정적 사이트라 별도 빌드 명령은 없습니다.

## 알림

알림 권한은 사용자의 버튼 클릭으로 요청합니다. 이 탭이 열려 있고 Supabase Realtime 연결이 살아 있는 동안 새 메시지를 알립니다. 브라우저를 완전히 닫았을 때의 푸시 알림은 별도의 Web Push 서버·구독 설정이 필요합니다.

## 소셜 기능 (프로필 · 친구 · DM · 태그)

- **프로필 카드**: 이름이나 사진을 누르면 가입 시기, 역할, 소개, 태그, (친구면) 온라인 상태를 봅니다. 다른 사람에게는 나만 볼 수 있는 **메모**를 남길 수 있어요.
- **프로필 꾸미기**(계정): 글꼴 115종(Google Fonts, 사용하는 글꼴만 불러옴), 닉네임 굵기, 닉네임 색, 소개, 태그. 관리자의 무지갯빛 닉네임은 그대로 유지됩니다.
- **태그**: 계정 이용자가 이미지(찾아보기·끌어놓기·Ctrl+V)와 이름으로 만들고, 누구나 같은 태그를 골라 최대 3개까지 붙입니다. 만든 사람과 관리자가 삭제할 수 있어요.
- **친구 · DM**: 계정 이용자끼리 요청·수락하고, 다른 방에 있어도 DM을 보냅니다. 온라인/오프라인은 Realtime Presence로 친구에게만 표시합니다.
- **멘션**: 입력창에서 `@`를 치면 방 참여자가 자동완성되고, 나를 언급한 메시지는 강조·알림됩니다.
- **내 메시지 삭제**, **기간 내보내기**(방장·관리자, 1분/5분/하루).

`social_migration.sql`을 Supabase SQL Editor에서 한 번 실행해야 위 기능이 동작합니다. 다시 실행해도 안전합니다(기존 방·메시지·계정은 유지). 실행 전에는 친구·태그·꾸미기 저장과 시간 지정 내보내기가 오류 안내를 띄웁니다.
